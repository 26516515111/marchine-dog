# 火焰检测 V2.2 稳妥后处理设计

## 目标与前提

V2.2 的最终目标是从每张图片中输出一个最大主体火焰框。预测数据保证每张
图片都存在火焰，因此允许在没有候选框达到置信度阈值时，从全部模型候选框中
强制选择一个最优框。

密集火颗粒不需要逐个正确检测，但不能通过颜色加分或合框机制聚合成比主体
火焰更优的候选结果。

## 选择策略

V2.2 使用单一、可解释的候选排序规则：

```text
weighted_score = detection_score * normalized_bbox_area ** 0.3
```

其中：

- `detection_score` 是模型原始置信度。
- `normalized_bbox_area` 是检测框面积除以原图面积。
- 面积指数固定为 `0.3`，适度偏向大框，但不让低置信度的大误框仅凭面积胜出。

处理流程为：

1. 只保留带有合法 `bbox` 的 `fire` 或 `firebig` 候选。
2. 使用调用参数 `fire_threshold` 作为唯一候选阈值，默认值为 `0.25`。
3. 若存在达到阈值的候选，对这些候选按 `weighted_score` 排序。
4. 若没有候选达到阈值，由于每张图保证存在火焰，继续从全部合法候选中按
   `weighted_score` 强制选择一个。
5. 若模型没有产生任何合法候选，返回空结果；后处理不能凭空生成检测框。

## 删除和保留的行为

删除 V2.2 中以下 HSV 置信度后处理：

- 检测框 HSV 统计。
- 橙色像素占比判断。
- 饱和度分位数判断。
- 置信度乘 `1.2`。
- 为上述判断而对每张图片进行的原图二次读取。

删除固定的 `ATMOS_FIRE_THRESHOLD_SCORE=0.20` 及
`min(fire_threshold, ATMOS_FIRE_THRESHOLD_SCORE)`。阈值只有一个来源，避免
调用方将阈值提高后仍被隐藏的 `0.20` 覆盖。

保留：

- `ATMOS_FORCE_SELECT=True`，对应“每张图一定有火焰”的数据约束。
- `area_alpha=0.3`。
- 导出模型内部已有的 NMS。
- `MERGE_CLOSE_BOXES=False`。近框合并实现可继续保留以兼容显式调用，但默认
  路径不得启用。
- 现有 `firebig` 输出格式。

## 不采用的方案

不使用纯面积最大策略，因为密集颗粒可能被模型预测成一个低置信度大框。

不在本次加入连通域、颗粒密度或颜色形态学判断。这些规则需要单独标注的密集
颗粒验证集调参，否则会引入新的场景偏差。

## 测试

新增或调整 V2.2 后处理测试，覆盖：

1. 达到阈值的候选中，按置信度和面积的加权结果选出主体火焰。
2. `force_select=False` 时，所有候选低于 `fire_threshold` 返回空结果，证明
   不再存在隐藏的 `0.20` 阈值。
3. 默认强制选择模式下，所有候选低于阈值时仍按同一加权规则选择一个框。
4. 橙色像素不再改变候选置信度或选择结果。
5. 近框合并默认关闭。
6. CLAHE 训练和推理一致性测试继续通过。

## 验收标准

- V2.2 推理路径不再读取原图进行 HSV 置信度修正。
- V2.2 只有一个候选置信度阈值，默认 `0.25`。
- 默认情况下不合并相邻或重叠的颗粒框。
- 每张图有模型候选时默认输出一个按加权规则选出的框。
- 没有任何合法模型候选时不伪造框。
- 新增测试和 V2.2 现有相关测试全部通过。
